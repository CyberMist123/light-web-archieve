## 游客 probe

本轮使用新的无凭据 HTTP 请求、移动 UA、跟随短链，不借用现有浏览器登录态。
POC 样本 A `https://xhslink.cn/o/2yNuSBjolWo` 与 D `https://xhslink.cn/o/4YDvlxSgZAQ` 都返回 HTTP 200，存在 `__INITIAL_STATE__`，但 `note.noteDetailMap` 为空。
因此本次未获取正文、图片列表、评论或附件 metadata，不能从这两个结果证明免登录读取可行。
历史 POC 的“附件 metadata 游客可达”保留为历史条件下的结果，不推广为现在所有链接或完整归档均免登录。

## 为什么尚未合并成一个登录态

本机运行中的读取服务日志仍显示 `loaded … cookies from file`；私密收藏组件源码使用持久 profile，且本地新版源码与运行二进制不同。
`sessioncheck` / `momologin` 含固定作者账号校验，不适合作为陌生用户的登录程序。统一入口使用已有通用持久登录程序，并用收藏列表复核。
不能用“磁盘上新版支持”推断正在运行的生产服务已经支持；本轮没有替换、重编译或重启该生产服务。

从实现上，单账号覆盖三项能力需要它们共用同一浏览器会话，并串行执行浏览器操作。附件继续点击网站的原有下载按钮，不需要重新实现签名。
当前服务尚无已验证的同会话附件下载入口，所以本轮保留独立附件登录。将同一主号在两套浏览器分别扫码可能顶掉会话；这不是已打通的单账号支持，也不能承诺不会触发站点风控。

## 验证边界

- 补验：真实 Obsidian 无障碍树可见目录篇数旁「⚠ 同步暂停 · 登录」与账号弹窗。真实同步失败写入本地状态，不依赖 TG；登录不会伪造同步成功。扫码期间旧组件返回 500 导致提前退出的问题已修复，成功/超时页面会明确反馈；实际扫码保存及同步恢复仍以实测结果为准。

- 干净环境真实 CLI 子进程：临时用户目录、临时 vault、禁用作者组件/图片识别/模型目录、读取服务未连接。退出码 0，基础 ready；读取 disconnected；收藏/附件/AI unconfigured；doctor 未创建运行配置目录。
- 本机真实状态：基础/插件/Dataview 可用，读取与收藏组件报告登录失效。附件读取现有持久浏览器后确认已登录；正常关闭后再次启动仍能检测到已登录（未扫码）。
- 单元测试覆盖首次未登录、已登录不重新扫码、二维码成功后 doctor ready、超时、连接失败不伪报过期、收藏空列表、可选组件缺失、实际宿主配置目录、附件同页检测及专属会话关闭。
- 官方 Windows 组件真实下载、临时目录与独立端口启动、健康检查、真实二维码返回已通过；没有扫码，测试进程已清理，未修改原服务。editable package 安装成功；若 Python Scripts 不在 PATH，使用 `python -m link_brain`。
